# 🔗 Encadenando Inteligencia: Primeros Pasos con LangChain y OpenAI

## Contexto

Esta práctica introduce el uso de LangChain como framework para orquestar modelos de lenguaje grande (LLMs) de OpenAI. El objetivo es familiarizarse con la instanciación de modelos, el control de parámetros de generación, la construcción de prompts reutilizables mediante plantillas, la obtención de salidas estructuradas con Pydantic y la implementación de un pipeline RAG básico. Se trabajó en Google Colab ejecutando cada sección del assignment de forma incremental.

---

## 🎯 Objetivos

Al completar esta práctica se busca instanciar ChatOpenAI y realizar invocaciones básicas, controlar parámetros como temperature y max_tokens, diseñar prompts con ChatPromptTemplate y el operador LCEL, obtener salidas JSON/Pydantic fiables mediante with_structured_output, comparar enfoques zero-shot y few-shot para clasificación de sentimiento, implementar resúmenes con splitting de texto, extraer entidades estructuradas desde texto libre y construir un pipeline RAG elemental con FAISS.

## 🔬 Desarrollo

### ⚙️ Parte 0: Setup y Hello LLM

Se instalaron las dependencias con pip install incluyendo langchain, langchain-openai, langsmith y librerías auxiliares. Se configuraron las API keys de OpenAI y LangSmith en variables de entorno, aunque LangSmith generó errores 403 durante toda la práctica por permisos insuficientes.

Se instanció ChatOpenAI con modelo gpt-5-mini y temperature=0. Al invocar "Definí 'Transformer' en una sola oración", el modelo respondió describiendo la arquitectura como una red neuronal con mecanismos de autoatención para procesar secuencias en paralelo.

Para el fill in the blanks se completó MODEL="gpt-5-mini" y TEMP=0 siguiendo las pistas de usar temperature bajo para tareas evaluables. El modelo se identificó como ChatGPT de la familia GPT-4.

📝 **Reflexión:** Al pedir 1 vs 3 oraciones, el modelo ajusta la extensión manteniendo información esencial pero con diferente nivel de detalle. Con temperature=0 no se observa variancia entre ejecuciones idénticas, confirmando el comportamiento determinista esperado.

### 🎚️ Parte 1: Parámetros de decodificación

Se mantuvo MODEL="gpt-5-mini" y TEMP=0 para generar un haiku sobre evaluación de modelos. El resultado fue "Datos en calma / Mide error y verdad / Generaliza", mostrando que temperature=0 permite contenido creativo cuando el formato está especificado.

📝 **Reflexión:** Temperature=0 da máxima claridad y concisión, mientras valores altos (0.7-0.9) introducen creatividad pero variabilidad. En tareas cerradas con respuestas únicas, temperature bajo garantiza consistencia y reproducibilidad.

### 🧩 Parte 2: ChatPromptTemplate + LCEL

Se construyó un template con rol system ("asistente conciso y profesional") y rol human solicitando explicar un tema en ≤3 oraciones con ejemplo. Al encadenar con | (LCEL) e invocar con tema="atención multi-cabeza", el modelo explicó cómo cada cabeza atiende diferentes relaciones usando el ejemplo de traducción con correferencias.

📝 **Reflexión:** Few-shot conviene cuando el formato de salida es muy específico o el modelo tiende a desviarse del estilo deseado. Instrucciones claras bastan para tareas bien definidas. El template fija la estructura y el modelo se adapta consistentemente al formato especificado.

### 🧱 Parte 3: Salida estructurada

Se definió una clase Pydantic Resumen con campos title (str) y bullets (List[str]). Con with_structured_output se obtuvo un objeto válido con título "Riesgos de la prompt injection en LLM apps" y tres bullets sobre exfiltración de datos, comportamientos maliciosos y pérdida de integridad.

📝 **Reflexión:** Esta aproximación mejora frente a parsear JSON manualmente porque garantiza validación automática del esquema y elimina errores de formato. En producción, los contratos de salida estructurados son esenciales para integrar respuestas del LLM con APIs y bases de datos de forma confiable.

### 📏 Parte 4: Métricas mínimas

Se intentó enviar una traza a LangSmith pero falló con error 403 Forbidden. Esto indica que la API key configurada no tiene permisos adecuados o corresponde a OpenAI en lugar de LangSmith. La ejecución del chain completó correctamente a pesar del error de tracing.

📝 **Reflexión:** Los prompts con más contexto o que solicitan respuestas largas cuestan más tokens. Para balancear latencia vs calidad, se pueden usar respuestas cortas para chat interactivo y reservar respuestas completas para tareas de análisis donde el tiempo es menos crítico.

### 🧪 Parte 5: Mini-tareas guiadas

El traductor estructurado devolvió text="Excelente trabalho da equipe" con lang="portugués (Brasil)". El sistema Q&A respondió "No suficiente contexto" al recibir información insuficiente para la pregunta, demostrando el comportamiento esperado.

📝 **Reflexión:** El modelo alucina cuando el contexto es insuficiente, ambiguo o contradictorio con su conocimiento previo. Para exigir formato y concisión consistentes, se debe incluir la instrucción explícita de rechazar respuestas cuando no hay suficiente información y usar structured output para forzar el esquema.

### 🔄 Parte 6: Zero-shot vs Few-shot

Ambos enfoques clasificaron correctamente los tres textos como POS, NEG y NEU. La diferencia fue que few-shot prefijó las respuestas con "Etiqueta:" siguiendo el formato de los ejemplos, mientras zero-shot devolvió solo la etiqueta.

📝 **Exploración:** Aumentar el número de ejemplos mejora consistencia en casos ambiguos y ayuda a fijar el formato exacto de salida. Con temperature más alto (0.5-0.9) se introduce variabilidad en las respuestas, lo cual es indeseable para tareas de clasificación donde se busca determinismo.

### 📝 Parte 7: Resúmenes map-reduce

Se procesó un texto sobre vulnerabilidades de control de acceso dividido en chunks de 700 caracteres con overlap de 100. Se generaron bullets por chunk y se consolidaron en un resumen final describiendo la vulnerabilidad GET sin control de acceso y las mitigaciones mediante verificación de usuario y control de roles.

📝 **Exploración:** El resumen directo funciona para textos cortos, pero map-reduce es necesario cuando el texto excede el contexto del modelo. Chunk_size muy pequeño pierde contexto entre fragmentos, mientras chunk_overlap insuficiente puede omitir información en los bordes de los cortes.

### 🏷️ Parte 8: Extracción de entidades

Se usó un modelo Pydantic con campos opcionales (titulo, fecha) y lista de entidades tipificadas. Del texto de ejemplo se extrajo fecha="05/11/2025" y tres entidades: OpenAI (ORG), Universidad Católica del Uruguay (ORG) y Montevideo (LOC). El título quedó None porque el texto no lo contenía.

📝 **Exploración:** Los campos opcionales (Optional[str]) permiten manejar casos donde no toda la información está presente sin generar errores. Los fallos típicos incluyen fechas con formato ambiguo (05/11 puede ser mayo o noviembre) y nombres propios poco comunes que el modelo no reconoce correctamente.

### 🔎 Parte 9: RAG básico con FAISS

Se indexaron tres documentos sobre LangChain en FAISS usando OpenAIEmbeddings. Con k=4 y un prompt que instruye responder solo con contexto, al preguntar sobre la ventaja de RAG el sistema recuperó los documentos relevantes y respondió que RAG combina recuperación + generación para mejor grounding.

📝 **Exploración:** Valores de k muy bajos pueden perder información relevante, mientras k muy alto introduce ruido de documentos no relacionados. FAISS es eficiente para búsquedas en memoria, mientras Chroma ofrece persistencia en disco y mejor manejo de metadatos, aunque con mayor latencia inicial.

Esta práctica permitió experimentar con los componentes fundamentales de LangChain. La separación entre prompts, modelos y cadenas mediante LCEL facilita la modularidad del código.
