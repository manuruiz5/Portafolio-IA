# 🤖 Orquestando Inteligencia: Agentes Conversacionales con LangGraph, RAG y Memoria Dinámica

## Contexto

Los sistemas conversacionales modernos han evolucionado más allá de chatbots simples hacia **agentes inteligentes** capaces de razonar, usar herramientas externas y mantener contexto conversacional. **LangGraph** permite modelar estos agentes como **grafos de estado**, donde cada nodo representa una capacidad específica (razonamiento LLM, búsqueda RAG, gestión de memoria) y las aristas definen flujos de control dinámicos.

Esta práctica construye desde cero un agente multi-herramienta que integra: (1) **RAG** con FAISS para fundamentar respuestas en documentación real, (2) **Tool calling** para invocar funciones externas según necesidad, (3) **Memoria conversacional** mediante resúmenes dinámicos, y (4) **Interfaz Gradio** para pruebas interactivas. El desafío es diseñar un sistema donde el LLM decida autónomamente cuándo usar herramientas, cómo combinar información y cuándo responder directamente.

---

## ⚙️ Objetivos

* **Diseñar un AgentState robusto** con soporte para mensajes multi-turno y resúmenes opcionales.
* **Implementar RAG como tool reutilizable** mediante vector search sobre embeddings OpenAI + FAISS.
* **Integrar tool calling dinámico** donde el LLM selecciona herramientas (RAG, estado de pedidos, tiempo UTC).
* **Construir grafo LangGraph con ciclos**: Assistant ↔ Tools ↔ Memory con routing condicional.
* **Desplegar interfaz Gradio** para pruebas interactivas con log de herramientas usadas.

## Desarrollo

### 🔧 Paso 1-2: Setup y Estado Extendido

**Decisiones técnicas:**

- Librerías: `langgraph>=0.2.0`, `langchain-openai`, `faiss-cpu` para RAG sin GPU
- API keys: OpenAI configurada, LangSmith opcional para telemetría
- `AgentState`: `messages` con `operator.add` (acumulativo) + `summary: Optional[str]` para resúmenes

**Fill in the blanks completados:**

- Importar `START, END` desde `langgraph.graph`
- Modelo: `gpt-4o-mini` (balance costo/performance)
- `assistant_node`: Invoca `llm.invoke(state["messages"])` con historial completo

**Resultado:** Agente mínimo funcional que responde conversacionalmente. El estado viaja explícitamente por el grafo, permitiendo composición de nodos.

**Reflexión - ¿Por qué `Optional[str]` en summary?**
Permite inicializar en `None` y actualizarlo periódicamente. Ventaja: comprimir conversaciones largas (10K+ tokens) en resúmenes de 200 tokens para eficiencia.

### 📚 Paso 3-5: RAG y Tools Adicionales

**Arquitectura RAG:**

```
Textos → RecursiveCharacterTextSplitter (chunk_size=300) 
      → OpenAIEmbeddings 
      → FAISS Vector Store 
      → Retriever (k=3)
```

**Tool RAG:**

- Decorador `@tool` expone `rag_search(question)` al LLM
- Retriever busca por similitud coseno y concatena top-3 chunks
- Retorna texto plano (no JSON) para facilitar comprensión del modelo

**Tools dummy:**

- `get_order_status(order_id)`: Diccionario `{"ABC123": "En preparación"}`
- `get_utc_time()`: Retorna `datetime.utcnow().isoformat()`

**Fill in the blanks:**

- Descripción tool: "*Busca información en la base de conocimiento sobre LangGraph/RAG*"
- Mensaje sin resultados: "*No encontré información relevante...*"
- Parameter `k=3` en similarity_search

**Reflexión - ¿Cómo escalar con corpus grande?**

1. Vector store cloud (Pinecone/Weaviate) vs FAISS local
2. Chunking semántico respetando párrafos
3. Metadata filtering (fecha, categoría)
4. Reranking con Cohere/CrossEncoder
5. Embeddings más baratos (`text-embedding-3-small`)


### 🧠 Paso 6-9: Grafo con Tool Calling y Multi-turno

**Arquitectura del grafo:**

```
START → assistant → ¿tool_calls?
                    ├─ Sí → tools → assistant (ciclo)
                    └─ No → END
```

**Routing condicional:**

- Inspecciona `AIMessage.tool_calls` del último mensaje
- Si existen tool_calls → ejecutar `ToolNode` y volver a assistant
- Si no → terminar conversación

**Ejemplo de flujo (Turno 2):**

1. **Input:** "Usá tu base de conocimiento y decime qué es RAG"
2. **Assistant:** Genera `tool_calls: [{"name": "rag_search", "args": {"question": "qué es RAG"}}]`
3. **Tools:** Ejecuta `rag_search` → Retorna contexto de FAISS
4. **Assistant:** Sintetiza respuesta usando contexto: "*RAG combina recuperación + generación...*"
5. **Route:** No más tool_calls → END

**Reflexión - ¿Cómo manejar 10+ tools?**

- **Routing jerárquico**: LLM clasifica query en categorías, luego elige tool específica
- **Descriptions optimizadas**: Nombres claros + palabras clave en descripciones
- **Few-shot examples** en system prompt mostrando cuándo usar cada tool

---

### 🧪 Paso 10-11: Memoria Ligera con Summary

**Nodo de memoria:**

- Extrae últimos 6 mensajes del historial
- Prompt al LLM: "*Resumí en 3 bullets lo más importante + resumen previo*"
- Actualiza `state["summary"]` con respuesta

**Integración en grafo:**

```
tools → memory → assistant (con summary actualizado)
```

**Estrategia de actualización:**

- Cada 3 turnos completos (6 mensajes)
- Después de llamadas a RAG (información nueva relevante)
- Forzar si conversación >20 mensajes

**Resultado:** Summary automático captura acuerdos, decisiones y preferencias sin reproducir toda la conversación.

**Reflexión - ¿Qué excluir del summary?**

- ❌ PII (emails, teléfonos, direcciones)
- ❌ Credenciales o tokens
- ❌ Conversación social irrelevante ("¿cómo estás?")
- ✅ Decisiones, problemas reportados, preferencias del usuario


### ⚡ Paso 12: Interfaz Gradio Interactiva

**Componentes implementados:**

- `gr.Chatbot`: Visualización de historial conversacional
- `gr.Textbox`: Input del usuario
- `gr.State`: Mantiene `AgentState` entre interacciones
- `gr.Markdown`: Log de herramientas usadas por respuesta

**Función callback:**

1. Agregar `HumanMessage` al estado
2. Ejecutar `graph.invoke(state)`
3. Extraer `tool_calls` del último mensaje AI
4. Formatear chat history
5. Retornar: historial actualizado + nuevo estado + log de tools

**Resultado:** App pública desplegada en `https://3db1abf7ac1edf0043.gradio.live` (expira en 7 días). Permite probar conversaciones sin ejecutar celdas de Colab.

## 💭 Reflexión

Este proyecto demuestra que **LangGraph transforma la complejidad de agentes multi-herramienta en arquitecturas declarativas y debugeables**. Tres hallazgos clave:

### 1. El estado explícito es liberador, no restrictivo

A diferencia de frameworks que ocultan el estado, LangGraph lo hace **first-class citizen**. Esto permite:

- Inspeccionar cualquier punto del flujo para debugging
- Serializar/deserializar conversaciones para persistencia
- Implementar time-travel debugging (revertir a estados anteriores)

### 2. Tool calling no es magia, es routing inteligente

El LLM no "sabe" usar tools por arte de magia. Necesita:

- **Descriptions claras** que expliquen cuándo usar cada tool
- **Few-shot examples** mostrando patrones de uso correcto
- **System prompts** que establezcan reglas de decisión

Sin esto, el modelo llamará tools irrelevantes o fallará en casos ambiguos.

### 3. La memoria no es opcional en producción

Conversaciones reales superan los 10-20 turnos. Sin memoria ligera:

- El contexto crece linealmente → costo exponencial
- El modelo pierde coherencia → olvida decisiones previas
- Rate limits se alcanzan rápidamente

Un summary bien diseñado captura el 80% del contexto relevante en el 20% del espacio.
